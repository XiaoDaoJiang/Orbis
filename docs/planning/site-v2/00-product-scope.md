# 00 · 产品范围与内容能力

## 1. 产品定义

Orbis 是一个面向长期积累的技术内容与知识发布系统。它既要支持连续更新，也要支持深度表达和长期复用。

它不是单一的新闻站、博客模板或幻灯片仓库，而是把以下能力统一起来：

```text
发现与研究
    ↓
结构化内容
    ↓
多种发布形态
    ├── 阅读版
    ├── 演示版
    ├── 专题聚合
    ├── 长期知识条目
    └── RSS
```

## 2. 目标内容类型

### Blog / Essays

用于深度文章、观点论证、工程实践和完整教程。优先使用 Markdown，避免让普通内容直接携带 UI 代码。

### Daily / Weekly

作为 `Brief` 内容类型的不同发布节奏，而不是预先锁定的品牌专栏：

- `daily`：当天高信号变化与可执行判断；
- `weekly`：跨多天的趋势合并、升温/降温与下周观察；
- 未来可扩展 `ad-hoc`、`monthly`，不影响整体模型。

### Slides

演示是一种输出形态：

- Daily / Weekly 可以自动生成固定格式 Slidev 演示；
- 独立技术分享可以拥有自己的 Presentation 内容；
- Slides 不复制维护核心事实和引用。

### Topics

用于维护稳定的主题词表和聚合页，例如 Agent Harness、MCP、Memory、AI Infra。Topic 不是文件夹标签，而是有说明、别名、关联和生命周期的内容实体。

### 长期知识归档

用于保存不随单日新闻失效的知识：

- 架构模式；
- 技术概念；
- 项目研究；
- 工程决策；
- 经过核验的长期参考资料。

知识条目应支持 `draft / active / needs-review / archived` 状态和复查日期。

### RSS

同时支持两个方向：

1. **RSS 输入**：通过受控 Feed 配置发现候选信息；
2. **RSS 输出**：发布 Orbis 的最新内容，供阅读器订阅。

## 3. 目标用户体验

- 首页可以快速理解 Orbis 最近关注什么；
- 内容既适合搜索和手机阅读，也适合全屏分享；
- 每个内容实体都有永久 URL；
- 阅读版和演示版可互相跳转；
- 主题页能够跨 Blog、Brief、Slides 和 Knowledge 聚合；
- 历史内容不是日期文件列表，而是可筛选、可追溯、可复查的知识库。

## 4. 非目标

第一阶段不建设：

- 在线 CMS 与多人编辑后台；
- 登录、评论、点赞和用户画像；
- 服务端数据库与动态 API；
- AI 在线问答或 RAG 服务；
- 多语言站点；
- 复杂动画编辑器；
- 预先设计大量固定栏目。

## 5. 成功标准

规划落地后的最小成功标准：

1. 同一份 Brief 数据可生成 Astro 阅读版和 Slidev 演示版；
2. Blog、Brief、Topic、Knowledge 均通过 Schema 校验；
3. GitHub Actions 可生成单一 Pages Artifact；
4. 根站、内容页、演示子路径、RSS 均可公开访问；
5. 自动内容任务只需提交内容文件；
6. 旧静态页面在迁移期间保持可访问或具有明确重定向。
