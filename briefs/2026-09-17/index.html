Agent Runtime 开始分成多速执行栈，持续对话、深思考与快决策各自独立

Gemini 3.8 Live 与 StepAudio 3 Realtime 把对话、工具调用和后台推理压进连续实时循环，TypeSafe Jev 则把结构化概率决策做成独立的低延迟模型原语；与此同时，Claude for Small Business 将调度、审批和连接器权限包装成可配置工作流。Agent 工程正在从“一个模型完成全部任务”转向持续交互、深度推理、快速决策与受控业务执行分层协作的多速 Runtime。

Four signals

  • 实时 Agent 正把对话与后台工具执行解耦

    Gemini 3.8 Live 可在持续流式语音的同时异步执行 API 与工具调用，用户前台交互不再必须等待每个后台动作完成。

  • 深思考开始成为实时会话中的并行通道

    Gemini 3.8 Live Extended Thinking 与 StepAudio 3 Realtime 都强调在保持自然对话的同时进行更复杂推理，前台响应与后台计算正在成为两条可并行路径。

  • 机器原生的快速结构化决策正在形成独立模型层

    TypeSafe Jev 放弃自由字符串生成，直接返回类型安全的概率决策并并行采样，适合路由、评分、抽取与守卫等高频控制任务。

  • 业务 Agent 的控制面正在产品化为调度、审批与权限

    Claude for Small Business 将预置工作流、连接器、定时执行和逐工作流审批模式组合起来，说明长期业务 Agent 需要显式的运行策略而不仅是 Prompt。

实时对话不再阻塞后台工具与深度推理

Voice Agent 的关键架构变化不是单纯降低首字延迟，而是让前台会话、后台工具调用与复杂推理同时推进；因此任务状态、取消语义和副作用确认需要脱离单轮回复单独管理。

  • Google 表示 Gemini 3.8 Live 支持 asynchronous function calling，可以在继续向用户流式返回音频的同时在后台执行 API 与工具调用。证据：Build real-time voice applications with Gemini 3.8 Live and 3.5 Transcribe
  • Gemini 3.8 Live Extended Thinking 支持 configurable thinking，可在主对话继续响应或播报进度时在后台处理复杂的多步推理。证据：Build real-time voice applications with Gemini 3.8 Live and 3.5 Transcribe
  • Gemini 3.8 Live 支持实时视觉上下文，并覆盖 97 种以上语言，使同一实时会话可以同时消费语音、视觉与语言上下文。证据：Build real-time voice applications with Gemini 3.8 Live and 3.5 Transcribe
  • Google 的 Gemini 3.8 Live 发布说明展示了 Extended Thinking 协调多步预订与异步函数调用，同时保持连续自然对话。证据：Introducing Gemini 3.8 Live and 3.8 Live Extended Thinking

限制：实时保持对话并不代表后台工具调用天然安全，涉及写操作时仍需要独立权限、幂等和确认边界。；Google 的性能与体验数据主要来自官方发布和官方评测，具体业务场景仍需自行测量延迟、打断恢复与任务正确率。

Full-duplex 正从语音体验升级为任务执行协议

当用户可以随时插话、模型可以边说边想并在需要时调用工具，Voice Agent 的 Harness 必须处理并发输入、打断、在途动作和上下文更新，而不能继续假设严格的“听完再做、做完再说”串行循环。

  • StepAudio 3 Realtime 将 true full duplex 作为核心能力，允许用户在模型发言过程中插话、补充想法或打断，而不必等待一个完整轮次结束。证据：Step-Audio 3 Realtime
  • StepAudio 3 Realtime 明确支持 think while speaking，简单问题快速回应，更复杂问题可以在持续语音交互中进行更深入处理。证据：Step-Audio 3 Realtime
  • StepAudio 3 Realtime 的官方说明称模型在理解用户意图后可以使用工具完成任务，而不仅停留在语音问答。证据：Step-Audio 3 Realtime
  • StepFun 官方页面报告 StepAudio 3 Realtime 在 τ-Voice 上得到 56.0 分、在 AA Full-Duplex Bench 上得到 98.9 分，这些结果用于同时衡量 Voice Agent 任务能力与双工交互质量。证据：Step-Audio 3 Realtime

限制：这些 benchmark 分数来自模型提供方页面，不能替代独立环境中的任务成功率、打断恢复和工具副作用测试。；Full-duplex 会显著增加状态并发复杂度，用户新的语音输入可能与仍在执行的后台动作发生竞争。

Agent 控制面开始需要专门的快速决策模型

对路由、评分、守卫和高频分支而言，自由文本生成并不是唯一合适的智能接口；把结构、概率与低延迟直接做进模型，可以为慢速主 Agent 提供更稳定的 fast path，但其可靠性仍必须通过独立校准验证。

  • TypeSafe 的 Jev 不生成自由字符串，而是根据预先定义的输出结构返回类型安全的值，并为决策附带概率与置信度。证据：Introducing System One Models and Jev
  • TypeSafe 表示 Jev 的输出采用并行采样，在一次查询中生成全部决策，而不是像自回归 LLM 一样逐 token 顺序生成。证据：Introducing System One Models and Jev
  • TypeSafe 将 Jev 的目标场景定义为 classify、route、score、extract、branch 等软件工作流决策，以及对 LLM Prompt、推理轨迹和输出进行评分或守卫。证据：Introducing System One Models and Jev
  • TypeSafe 官方报告 Jev 在其 System One 形态任务上的端到端延迟约为 70 至 500 毫秒，并声称相较所对比的前沿模型可达到约 40 至 200 倍速度提升。证据：Introducing System One Models and Jev

限制：Jev 当前处于 early access，速度、成本和工作流评测均由厂商自报，生产采用前需要独立基准和概率校准检查。；类型安全只能保证输出形状符合约束，并不保证决策语义一定正确；错误但类型合法的高置信度判断仍需被检测。

长期业务 Agent 正把审批与调度变成 Runtime 配置

当 Agent 能跨多个 SaaS 长期运行时，是否自动执行、何时执行以及能操作哪些数据必须成为逐工作流可配置策略；把这些边界放进产品控制面比依赖 Prompt 自律更可审计。

  • Anthropic 在 2026-09-15 宣布 Claude for Small Business 包含 43 个工作流，并新增 27 个集成来覆盖更多业务工具。证据：Claude for Small Business launches new workflows, integrations, and training programs
  • Claude for Small Business 的插件允许用户在设置时为具体工作流配置周期，使其可以按所选计划自动运行。证据：Claude for Small Business launches new workflows, integrations, and training programs
  • Anthropic 表示每个工作流默认从 approval mode 开始，Claude 先准备工作并等待用户确认；用户可以在熟悉后逐工作流改为自动运行，并可随时切回审批模式。证据：Claude for Small Business launches new workflows, integrations, and training programs
  • Claude for Small Business 继续遵循已有业务软件权限，用户在 QuickBooks 或 Google Drive 等系统中原本不可见的数据不会因为通过 Claude 访问而获得额外权限；部分高风险流程还会停在最终提交之前。证据：Claude for Small Business launches new workflows, integrations, and training programs

限制：这是面向中小企业的产品工作流，不代表其审批粒度和连接器权限模型可以直接覆盖高风险生产系统。；自动计划与审批模式解决的是触发和授权问题，仍需要幂等、重试、审计日志和失败恢复等运行时机制。

下一代 Agent 更像多速执行栈而不是单模型循环

实时交互、深度推理、快速结构化决策和受控业务执行正在形成不同延迟与风险等级的执行层；工程上应显式设计路由、状态和权限，让不同层各自承担最适合的工作，而不是让一个通用模型承担全部控制职责。

  • Gemini 3.8 Live 可以在前台持续对话时异步执行工具，Extended Thinking 还能在保持会话流的同时运行更复杂的后台推理。证据：Introducing Gemini 3.8 Live and 3.8 Live Extended Thinking · Build real-time voice applications with Gemini 3.8 Live and 3.5 Transcribe
  • StepAudio 3 Realtime 同时提供 full-duplex 交互、边说边思考与工具调用能力，说明实时 Agent 的交互层与执行层正在被放入同一个并发循环。证据：Step-Audio 3 Realtime
  • Jev 将类型安全概率决策与并行采样组合成面向软件工作流的快速模型原语，可作为通用生成式 Agent 之外的独立决策路径。证据：Introducing System One Models and Jev
  • Claude for Small Business 把定时运行、逐工作流审批与既有 SaaS 权限组合到同一工作流层，提供了持续业务执行所需的治理外壳。证据：Claude for Small Business launches new workflows, integrations, and training programs

限制：多层模型与工作流可以降低单个组件负担，但会增加路由策略、状态同步、可观测性和端到端验证复杂度。；不同厂商的产品接口尚未形成统一标准，跨模型与跨 Runtime 的切换仍需要应用自行定义兼容合同。

From signals to action

  • 为 Agent 定义 fast path 与 deep path

    把分类、路由、置信度判断等低延迟决策与复杂规划、长链推理分开，并记录每次路由选择、模型版本和失败回退。

  • 把实时会话改造成并发状态机

    明确用户打断、后台工具调用、在途推理、取消与新输入之间的优先级，避免继续依赖严格串行的 request-response 假设。

  • 将审批策略下沉到工作流配置

    对每个持续运行任务声明触发频率、可写系统、最终确认点和自动执行级别，并让这些策略独立于 Prompt 可审查、可回滚。

  • 为结构化快决策建立独立校准集

    使用真实路由、守卫与评分样本测试概率校准、错误类型和阈值稳定性，不把类型安全或厂商速度指标等同于业务正确率。
