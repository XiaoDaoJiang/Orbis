Agent 进入可验证执行阶段：推理证明、身份委派、运行时安全与真实任务评测补齐信任链

Anthropic 的 FlashProve 探索用零知识证明验证推理是否符合承诺的模型权重；Claude Enterprise Managed Auth 与 MiniMax BYOB Table 将组织身份和跨 Agent 行动授权纳入协议；OpenAI 推进真实生活工作流评测与生成时 activation probes；腾讯 WeVisOne-VL 将视觉理解扩展到坐标、分割和像素级结果。Agent 工程正从能调用工具转向谁在执行、执行了什么、如何证明和评估。

Four signals

  • 模型推理开始具备可独立验证的密码学证明路径

    FlashProve 将模型权重承诺与推理证明组合，让客户端检查输出是否符合指定模型计算；但当前证明成本和覆盖范围仍有限。

  • Agent 连接与协作协议显式表达身份和行动授权

    Enterprise Managed Auth 将组织身份映射为 MCP 访问令牌；BYOB Table 将签名能力卡、所有者审批和执行回执纳入多 Agent 协作。

  • Agent 评测从聊天质量转向真实工作流完成度

    LifeVal 以照护、财务、教育、购物和政府服务等日常任务衡量个人 Agent 的行动能力，强调完成工作流而不只是生成建议。

  • 运行时安全与视觉感知向结构化能力下沉

    Activation probes 在生成中逐 token 监测潜在违规行为；WeVisOne-VL 以统一输出覆盖定位、OCR、分割和 matting。

推理来源验证开始从服务商声明走向可验证计算

模型托管场景不仅需要知道服务商声称运行了哪个模型，还需要验证输出是否来自预先承诺的权重。零知识推理证明提供了新方向，但当前成本更适合高价值或抽样审计场景。

  • FlashProve 使用零知识简洁证明验证推理结果符合模型权重承诺，同时不泄露权重；其技术报告描述了基于哈希的协议，并将安全分析形式化到 Lean。证据：FlashProve: an open-source library for provable inference
  • 技术报告展示对 400B 参数 Llama 4 Maverick 的实验：单张 H100、24 个 CPU 核、232 GB 主机内存；每个 1,024-token 请求窗口只证明提示后的一个 greedy token。证据：FlashProve: an open-source library for provable inference
  • 报告中的 24 请求批次约需 223 秒、每份证明约 18.78 MB；按 GPU 计算，证明过程约比普通 prefill 慢 72 倍。证据：FlashProve: an open-source library for provable inference
  • Anthropic 的 GitHub 仓库将 FlashProve 标注为研究原型、未维护且不接受贡献，因此更适合作为密码学推理验证的技术样例，而非直接采用的生产依赖。证据：Anthropic FlashProve research prototype repository

限制：FlashProve 是未维护的研究原型；证明输出符合指定权重计算，不代表回答在语义上真实或正确。；当前演示只验证指定 token 的 greedy 选择，不等于整段生成或工具执行链的端到端证明。

MCP 身份委派与多 Agent 协作把所有权变成协议字段

Agent 连接还需回答组织如何授予身份、机器人能代表谁行动、能力范围由谁批准，以及跨 Agent 副作用如何留下记录。Claude 与 BYOB 分别从身份断言和行动账本切入。

  • Claude Enterprise Managed Auth 允许组织通过 IdP 或 Claude 签发的 JWT 身份断言授权 MCP connector；授权服务器验证 issuer、audience、client_id、过期时间和 jti 后再签发访问令牌。证据：Enterprise Managed Auth for connectors
  • Anthropic 文档说明 Enterprise Managed Auth 面向 Claude Team 与 Enterprise；IdP-managed 已普遍可用，Claude-issued 方式仍处于 beta。证据：Enterprise Managed Auth for connectors
  • MiniMax BYOB Table Protocol v0.1 使用 append-only ledger、所有者签名 capability cards 和拓扑策略；Agent 提议、受影响所有者批准、所有者自己的 Agent 执行、另一个 seat 验证。证据：BYOB Table Protocol

限制：免交互 OAuth 不等于免授权，connector 服务端仍须正确验证 JWT。；BYOB 是早期 v0.1 参考实现，协议设计值得研究，但生产成熟度尚待验证。

个人 Agent 的评测单位从回答转向跨工具工作流

真实个人助理任务涉及多步骤检索、比较、规划和外部操作；单轮回答正确率会漏掉工具执行、状态维护、约束遵循和交付确认。

  • OpenAI LifeVal 以美国和国际时间使用调查为基础，并补充覆盖 3,995 名受访者的代表性调查，识别个人助理最值得协助的日常任务。证据：LifeVal
  • LifeVal 覆盖照护、健康、教育、家庭事务、个人财务、购物和政府服务，强调用户需要的不只是建议或聊天回复，而是实际完成任务。证据：LifeVal

限制：LifeVal 由 OpenAI 构建并用于跟踪自家模型进展，结果应结合任务分布和独立复测理解。；完成率还需与授权、外部副作用正确性、失败恢复和人工接管成本一起衡量。

安全控制开始进入生成循环，而不只在输入和输出端过滤

对具备工具调用能力的 Agent，事后扫描完整回复可能太晚。基于模型内部 activation 的 probes 能在生成中途介入，但需要针对模型版本持续训练。

  • OpenAI 报告其部署 activation classifiers，利用模型内部 activations 逐 token 监测生成，可中途打断回复、阻止工具调用，或暂停生成交由推理模型审查。证据：Training activation classifiers for safety and alignment
  • OpenAI 表示，在其测试中 probes 对已测试 jailbreak 的鲁棒性高于文本分类器，并能跨多个 post-training checkpoint 迁移。证据：Training activation classifiers for safety and alignment
  • 该方法依赖被监测模型的内部 activations，监督信号只能覆盖明确训练过的行为；更换基础模型或权重变化后可能需要重新训练。证据：Training activation classifiers for safety and alignment

限制：Activation probes 不能替代最小权限、工具沙箱、外部策略检查和事后审计。；实际效果取决于训练覆盖、模型版本和阈值，仍需针对真实工具调用回归。

视觉模型把像素级感知变成 Agent 可消费的结构化接口

UI 操作、视觉检索和具身任务需要坐标、区域和像素级对象。WeVisOne-VL 将目标定位、OCR、分割和 matting 统一到结构化输出，有机会减少语言模型与专用视觉工具之间的接口转换。

  • 腾讯 WeChat Vision 的 WeVisOne-VL 支持目标检测、指代表达定位、计数、pointing、OCR、分割和 matting，可按需求输出点、框、mask 或 alpha matte。证据：WeVisOne-VL: Unified Visual Perception from Objects to Pixels
  • 项目页介绍其通过特殊 OBJ token 接入 9.6M 参数 pixel decoder，并以约 100M 张图像训练，报告在 30 多个 object-level 与 pixel-level benchmark 上领先。证据：WeVisOne-VL: Unified Visual Perception from Objects to Pixels

限制：30 多项 benchmark 的领先表现来自项目方报告，应在目标图像分布和真实交互任务上独立复测。；模型部署仍需核对显存、分辨率、依赖和推理吞吐。

From signals to action

  • 为关键模型调用设计推理 provenance

    在高价值场景记录模型版本、权重承诺、请求与响应摘要，评估抽样证明的成本和验证延迟。

  • 把 MCP 身份和工具权限分开建模

    分别定义用户身份、组织身份、connector token、agent capability 与每次外部副作用的审批者。

  • 用真实工作流替代单轮问答评测

    选取跨系统任务，记录成功率、步骤数、工具错误、用户确认点、失败恢复和人工接管成本。

  • 建立生成时安全与视觉结构输出回归

    测试 tool-call 中断策略、probe 漏报/误报，以及点框、OCR、mask 输出在真实 UI 操作中的定位准确率。
