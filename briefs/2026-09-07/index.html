Agent 的新边界正在变成显式策略层

工作区信任、工具访问、网络出口、凭据与外部生命周期监督正从隐式约定变成可验证策略；生产级 Agent 的竞争焦点正在从“会调用工具”转向“每个副作用都有边界、所有权和证据”。

Four signals

  • Workspace 本身就是安全边界

    Gemini CLI 的最新安全修复把环境变量变更、路径边界与系统级配置权限都纳入显式信任检查。

  • Tool Access 正在收敛到策略网关

    GitHub 的 Agentic Workflows 与 MCP Gateway 把只读默认、完整性过滤、调用次数和写入通道拆成独立控制面。

  • Egress 与凭据必须和 Agent 进程隔离

    Agentic Workflow Firewall 用网络 allowlist、API proxy sidecar、DLP 与运行时限制把外部副作用变成可审计资源。

  • 生命周期权限正在移出 Agent 主进程

    OpenClaw 更早已引入 external supervisor 模式，2026.9.2 继续强化升级、Gateway 重启与 reply recovery，说明 restart、自更新和会话恢复正成为独立控制面。

Gemini CLI 把 Workspace Trust 从提示语升级为执行约束

Coding Agent 的第一道安全边界正在前移到工作区、环境变量与系统级配置加载阶段。

  • Gemini CLI v0.60.0 nightly 在 2026-09-05 增加环境变更同意提示，并清理可能改变运行时行为的环境变量。证据：Gemini CLI v0.60.0 nightly 20260905
  • 同一版本强化 workspace 路径边界检查和符号链接解析，并将其用于 command safety 与 file discovery。证据：Gemini CLI v0.60.0 nightly 20260905
  • 同一版本对 system-wide configuration paths 执行更严格的权限与所有权检查。证据：Gemini CLI v0.60.0 nightly 20260905

限制：该版本属于 nightly 预发布，能力与默认行为仍可能继续调整。；这些修复降低宿主环境风险，但不能替代工具级权限和网络隔离。

Reasoning 与 Deterministic Execution 正在被明确拆开

生产自动化更适合让 Agent 负责判断，让构建、测试与受控写入继续由确定性工作流执行。

  • GitHub Agentic Workflows 官方建议 build、test、lint、deploy 与 reproducible scripts 等确定性操作继续使用 conventional GitHub Actions。证据：GitHub Agentic Workflows
  • Agent jobs 默认使用只读 GitHub 权限并在 sandbox 中执行；配置的 GitHub 写操作通常由独立 safe-outputs jobs 校验后以 scoped permissions 执行。证据：GitHub Agentic Workflows
  • gh aw compile 会验证 Agentic Workflow 源并生成由 GitHub Actions 执行的 .lock.yml workflow。证据：GitHub Agentic Workflows

限制：该设计深度绑定 GitHub Actions 运行模型，迁移到其他执行平台需要重新实现等价的权限与输出门控。；官方仍要求谨慎处理安全配置并保持人工监督，不能把安全默认值理解为零风险。

MCP Gateway 正从连接器变成 Tool Policy Plane

MCP 的生产化价值不只在统一调用协议，更在把来源完整性、调用额度和写入方向放到 Agent 外部执行。

  • GitHub MCP Gateway 的 guard policies 将 source server 的 allow-only 与 output server 的 write-sink 分开，用不同策略约束可读来源和写入 sink。证据：GitHub Agentic Workflows MCP Gateway
  • allow-only 可限制 public、owner/repo 范围与 minimum integrity，并支持 blocked-users、approval-labels 和 trusted-users。证据：GitHub Agentic Workflows MCP Gateway
  • tool-call-limits 可在调用 backend 前按 session 硬限制单个工具的调用次数；Gateway 同时提供 tool timeout 与 OpenTelemetry tracing 配置。证据：GitHub Agentic Workflows MCP Gateway

限制：策略粒度越高，配置和运维复杂度越高，需要版本化策略、测试样例和审计日志配套。；Gateway 控制的是工具边界，无法单独解决 Agent 在已授权工具内部做出错误业务判断的问题。

网络出口和模型凭据开始成为独立 Runtime 资源

高权限 Agent 不应直接拥有开放网络与模型密钥，egress policy 和 credential proxy 应成为 Harness 的一等组件。

  • Agentic Workflow Firewall 通过 Squid 对 outbound HTTP/HTTPS 实施 domain allowlist，并在容器化 agent 执行环境中集中控制网络出口。证据：GitHub Agentic Workflow Firewall Usage Guide
  • 可选 API proxy sidecar 负责持有认证凭据并安全注入 API keys，使 Agent 无需直接持有这些模型凭据。证据：GitHub Agentic Workflow Firewall Usage Guide
  • Firewall 提供可选 DLP、agent timeout、网络流量统计与 audit/log 分析能力，用于约束和追踪运行时副作用。证据：GitHub Agentic Workflow Firewall Usage Guide

限制：HTTPS URL path 级过滤需要启用 SSL Bump；只配置 domain allowlist 时不会检查完整 URL path。；不同 sandbox runtime 的网络隔离保证并不完全相同，生产采用前需要按实际执行路径验证 egress 边界。

Runtime 生命周期权限正在形成独立 Supervisor Boundary

Agent 自身不应同时拥有任务推理、服务生命周期、更新权限和凭据控制；这些高风险能力正被拆到可验证的外部监督层。

  • OpenClaw v2026.7.2-beta.2 已加入 OPENCLAW_SUPERVISOR_MODE=external，使外部 lifecycle owner 可接管 restart 与 deferral，同时阻止 native service mutation 和 self-update，并提供 versioned atomic restart-handoff consume contract。证据：OpenClaw v2026.7.2-beta.2
  • 同一 beta 版本还修复 Gateway restart admission 卡死、reply session finalization stall 后的恢复，以及 one-shot cron lifecycle claim race。证据：OpenClaw v2026.7.2-beta.2
  • OpenClaw v2026.9.2 的可靠升级与恢复能力会在自动更新中保留 active settings、enabled skills 和 default-agent ownership，并恢复 Git update 后的 Gateway restart。证据：OpenClaw v2026.9.2
  • v2026.9.2 还会在 Gateway restart 后恢复 active、queued 和 delegated replies，并支持更多 settings 由其 running owners 在线应用而无需重启。证据：OpenClaw v2026.9.2

限制：这是 OpenClaw 的具体实现，不代表行业已经形成统一 Supervisor 协议。；将生命周期权限外移只是缩小 Agent 权限面，外部 supervisor 本身仍需要身份、审计和失败恢复机制。

From signals to action

  • 给 Coding Agent 增加 Workspace Trust 检查

    在执行 shell 或加载项目配置前校验工作区根目录、符号链接、配置文件所有权与运行时环境变量来源。

  • 把 MCP 权限移出 Prompt

    用 Gateway 或 wrapper 明确限制可访问 repo、工具调用次数、超时和允许的写入 sink，不依赖模型自我约束。

  • 隔离网络出口与模型密钥

    为高权限 Agent 增加 egress allowlist，并通过独立 credential proxy 注入模型调用能力而不是直接暴露 API key。

  • 定义外部 Supervisor 交接协议

    将 restart、自更新、凭据和高风险配置变更移出 Agent 进程，并用版本化 handoff、审批绑定和审计记录约束生命周期操作。
