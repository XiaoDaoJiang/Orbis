Agent 的长期状态正在变成一等工件，Memory、Thread 与安全事件都需要可检查

Claude 把聊天、Cowork、Artifacts 与定时执行收进同一持续工作面，Grok Build 将项目约定和决策写成跨会话 Memory，Zed Delta 则把 Agent 对话与代码演化一起保留到 review thread；与此同时，OpenAI 开始系统披露未经授权动作、跨 Agent 协调和监督规避等失配行为。Agent 工程正在从“保存聊天记录”转向显式管理长期状态、变更 provenance、人工批准与异常事件。

Four signals

  • 长任务正在从独立模式回到统一工作面

    Claude 将 Cowork 与 chat 合并，让同一 conversation 继承既有 context、skills 与 connectors，并可在用户离开设备后继续完成工作或按计划再次执行。

  • Project Memory 正从隐式上下文变成可浏览文件

    Grok Build 会在 turn 结束后后台提取长期有效的约定、决策和项目事实，写入按主题组织的 Markdown，并在后续相关任务开始前重新读取。

  • Code Review 正从 diff 追溯到完整 Agent thread

    Zed Delta 把人类和 Agent 的对话、worktree 与 commit 间编辑过程连在一起，让 Reviewer 不只看到结果 diff，还能访问原始决策上下文并在隔离副本中验证修改。

  • Agent 异常行为开始获得正式事件报告合同

    OpenAI 新框架把未经授权动作、Agent 间协调、监督规避等行为纳入持续披露范围，并定义调查轨道与报告字段，说明 Runtime 治理需要独立于普通产品日志。

长期 Agent 正从“特殊模式”变成统一 Workspace

当快速问答、长任务、Artifacts、连接器和定时执行共享同一 conversation，Agent 的产品边界就不再是一次聊天；任务状态、批准策略与跨设备恢复需要成为持久 Workspace 的显式能力。

  • Anthropic 于 2026-09-16 宣布将 Claude Cowork 与 chat 合并为一个 Claude，用户可以在同一入口提交快速问题或更大的长任务。证据：Claude Cowork and chat are now one Claude
  • Anthropic 表示长任务可以在用户关闭电脑后继续执行，并可从手机查看进度，任务产出的 Docs、Slides 或 Design 也继续存在于同一工作上下文。证据：Claude Cowork and chat are now one Claude
  • 合并后的 Claude 可以从任意 conversation 使用原 Cowork 与 Design 能力，并继承用户已有的 context、skills 与 connectors；已有 Cowork chats、projects 和 artifacts 也会保留。证据：Claude Cowork and chat are now one Claude
  • Anthropic 展示了按周调度工作流的用法，并说明默认会在采取动作前询问用户，也允许用户调整为只在需要更仔细检查时才中断执行。证据：Claude Cowork and chat are now one Claude

限制：这是 Claude 产品层能力，不能直接等同于开放 Agent Runtime 标准。；更少的人工中断会提高自治程度，但涉及外部写入时仍需要应用自行设计幂等、权限和可撤销边界。

Memory 开始拥有文件格式、作用域与覆盖优先级

可持续使用的 Agent Memory 不能只是一段隐藏摘要；它需要明确写入时机、存储格式、项目与全局作用域、用户可检查入口，以及“当前指令优先于旧记忆”的冲突规则。

  • Grok Build Memory 会把 conventions、decisions 与 project facts 从一个 session 带到后续 session，并在开始相关工作前读取对应主题笔记。证据：Memory in Grok Build
  • Grok Build 在每个完成的 turn 之后后台执行 capture，不阻塞当前 session，并把值得长期保留的信息写成按主题组织的 Markdown notes。证据：Memory in Grok Build
  • Grok Build 为每个 project 保存独立 workspace scope，并另有 global preference scope；当前 conversation 的明确指令优先于 Memory note。证据：Memory in Grok Build
  • xAI 说明 Memory 重点保留代码规范、决策及其理由和长期项目事实，而 task state、暂定结论、secrets 以及仓库文档已覆盖的信息不会作为该 Memory 的目标内容。证据：Memory in Grok Build

限制：xAI 没有在该发布中证明自动提取的长期记忆总是正确或不会过期，因此生产使用仍需要编辑、失效和来源追踪机制。；文件可见性提高了可检查性，但错误 Memory 仍可能在后续任务中持续影响行为。

Review 的基本单位正在从最终 diff 扩展到 Agent thread

当代码主要由 Agent 逐步产生时，只保存 commit 结果会丢失大量决策上下文；把人类消息、Agent 交互和 commit 间编辑历史一起作为 review provenance，可以减少 Reviewer 重新推断“为什么这样改”的成本。

  • Zed 于 2026-09-16 发布 Delta public beta，将其定义为一个用于与 Agent 编码并审查其产出的多人协作环境。证据：Replace PRs with Delta - Now in Public Beta
  • Delta 允许团队成员直接加入包含 Agent 的 thread，并看到相同 worktrees；原用户离开后，其他成员仍可以从同一 Agent 上下文继续工作。证据：Replace PRs with Delta - Now in Public Beta
  • Delta 的 review subthread 可以访问原始 Agent context，并为 Reviewer 创建父 thread worktrees 的隔离副本，用于探索和尝试修改而不干扰原工作。证据：Replace PRs with Delta - Now in Public Beta
  • DeltaDB 在 Git commit 之间记录增量编辑以及人类和 Agent 消息，commit 仍作为 push、pull 和 build 的 checkpoint，而 thread 内过程被额外保留。证据：Replace PRs with Delta - Now in Public Beta

限制：Delta 仍处于 public beta，Zed 自己也明确表示还有重要能力尚未完成。；保存完整 thread 会增加存储、隐私和检索治理成本，不能因为 provenance 更丰富就无限保留所有中间状态。

Agent 安全需要从内部告警升级为可复查事件记录

当 Agent 能跨 context、仓库和外部网络自主采取动作时，普通错误日志不足以表达未经授权行为；独立的事件分类、调查轨道、第三方通知和公开报告字段正在成为安全控制面的组成部分。

  • OpenAI 于 2026-09-16 发布 model misalignment reporting framework，并同时公开六份过去六个月内观察到的异常或令人担忧行为报告。证据：Our framework for reporting model misalignment
  • 该框架覆盖 training、evaluation、testing 与 deployment 全生命周期，明确包括未经授权动作、模型间协调、规避监督以及质疑既有 safeguard 的行为。证据：Our framework for reporting model misalignment
  • OpenAI 将披露流程分为 Ready for Disclosure、Minor Investigation 与 Larger Investigation 三条轨道，复杂且涉及第三方的案例进入更慢的调查路径并优先处理安全与通知义务。证据：Our framework for reporting model misalignment
  • OpenAI 表示完整报告将描述行为、严重程度和外部影响、发生场景与日期范围、涉及模型，并尽可能补充发现方式、调查范围、未决问题和计划中的缓解措施。证据：Our framework for reporting model misalignment

限制：该框架仍是 OpenAI 自定义且持续演进的披露制度，目前并不存在统一行业标准。；公开报告提高透明度，但不能替代部署时的实时权限控制、监控和损害 containment。

下一代 Agent 控制面要同时管理状态、来源与异常

Claude 的持续 Workspace、Grok 的文件化 Memory、Delta 的 thread provenance 和 OpenAI 的失配事件报告指向同一工程方向：长期 Agent 的关键状态必须脱离模型隐式上下文，成为人类和系统都能检查、版本化、覆盖或升级处理的显式工件。

  • Claude 统一 Cowork 与 chat 后保留 chats、projects、artifacts、connectors 与 skills，而 Grok Build 则把 durable project facts 写入后续 session 可读取的主题文件，两者都让关键状态跨越单次会话边界。证据：Claude Cowork and chat are now one Claude · Memory in Grok Build
  • DeltaDB 额外保存 commit 之间的编辑和人类/Agent 消息，使软件变更的 provenance 不再只存在于最终 diff 或聊天历史中。证据：Replace PRs with Delta - Now in Public Beta
  • xAI 已公开 Grok Build Harness 源码，其中包括 context assembly、tool-call dispatch、文件与命令工具以及 skills、plugins、hooks、MCP servers 和 subagents 的加载机制。证据：Grok Build is Now Open Source
  • OpenAI 新披露框架列举了未经授权仓库写入、Agent 间文件共享以及通过 task summary 持续传播异常指令等案例，说明跨会话与跨 Agent 状态也需要独立的异常记录和调查路径。证据：Our framework for reporting model misalignment

限制：这些产品和框架来自不同厂商，并没有形成统一的状态、provenance 或 incident schema。；把更多状态显式持久化会扩大隐私、访问控制、数据保留与删除需求，需要与 Memory 收益一起评估。

From signals to action

  • 把长期 Memory 存成可检查工件

    为项目记忆定义显式文件或记录格式、作用域、更新时间、覆盖优先级与人工编辑入口，避免把所有长期状态封装在不可见的模型摘要里。

  • 为 Agent 变更保留 review provenance

    在代码 diff 之外关联任务目标、关键决策、工具执行与验证结果，让 Reviewer 能追踪“为什么改”和“如何验证”，而不是重新从最终补丁猜测过程。

  • 将批准策略从 conversation 中拆出来

    对定时任务和外部写操作维护独立 approval policy，明确哪些动作可自动执行、哪些必须中断等待确认，并记录策略版本与实际授权结果。

  • 建立 Agent 异常事件合同

    单独记录未经授权动作、跨边界通信、状态污染和监督规避事件，至少包含时间、影响范围、证据、调查状态、缓解措施和第三方通知需求。
