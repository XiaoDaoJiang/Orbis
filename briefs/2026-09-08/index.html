Agent 的瓶颈正在从模型能力转向 Harness 吞吐与运行契约

并行 Agent 已开始形成可度量的组织级劳动力，模型与 Harness 的协同优化继续提高任务吞吐；与此同时，人类 steering、API 漂移和长运行进程身份正成为新的规模化约束。

Four signals

  • 并行 Agent 劳动力已经跨过组织级阈值

    OpenAI 报告研究组织的 Agent 总运行量已超过人类工作量，Agent orchestration 开始需要像算力和队列一样被度量。

  • 模型与 Harness 的协同优化开始产生乘数效应

    GPT-6 Astra 与更新后的 Codex harness 在同一任务基准上组合提升完成速度，说明不能再只用模型分数评估 Coding Agent。

  • Human Steering 正在变成稀缺控制资源

    Agent 能承担更长、更复杂的任务，但高难任务仍需要显著人工 steering，瓶颈正在从生成 token 转向审阅与决策容量。

  • Runtime 正在把接口、版本与生命周期写成可检查契约

    OpenHands 用 pinned OpenAPI 管理客户端漂移，Codex 则把 executor build identity 与 PID generation 写入运行时边界。

Agent 劳动力开始成为组织级容量指标

当并行 Agent 的累计运行量超过人类工作量后，工程团队需要直接管理 Agent 并发、队列、预算和有效产出，而不只是统计调用次数。

  • OpenAI 表示其自动化 research intern 目标已经达到：在人员指导下，Agent 可以承担原本需要熟练研究人员数天完成的定义清晰研究任务。证据：Research acceleration: The view inside OpenAI
  • 截至 2026 年 8 月中旬，OpenAI 研究组织报告每 1 个 human workday 对应约 3.1 个 agent-workdays 的 Agent 运行量。证据：Research acceleration: The view inside OpenAI
  • OpenAI 描述研究人员同时运行多个 Coding Agent 的工作方式正在增加，并展示同时推进四个及以上 Agent 任务的典型工作流。证据：Research acceleration: The view inside OpenAI

限制：这些数字来自 OpenAI 自身研究组织，不能直接外推到其他团队的任务结构与生产率。；agent-workday 衡量的是运行投入而不是科研成果，更多运行时间不等于同比例的有效产出。

Agent 越能长跑，人类 Steering 越接近稀缺资源

长时 Agent 的下一个容量瓶颈不是单纯增加并发，而是为高价值决策保留足够的人类审阅、纠偏和停止能力。

  • OpenAI 报告研究人员正在把更高层级、更长时间跨度的工作委托给 Coding Agent，而不是只让 Agent 完成局部代码修改。证据：Research acceleration: The view inside OpenAI
  • OpenAI 的内部评估显示 2026 年 1 月到 7 月各难度任务的成功率上升，但任务复杂度提高时仍需要显著 human steering。证据：Research acceleration: The view inside OpenAI
  • OpenAI 明确保留由人来设定研究优先级，并决定何时扩大、暂停或部署研究结果与 Agent 工作流。证据：Research acceleration: The view inside OpenAI

限制：steering 强度会受到任务定义、工具权限和评测方式影响，不能只用统一的人机比例做容量规划。；厂商内部成功率提升不能替代团队在自身代码库和风险等级上的独立评测。

模型升级和 Harness 升级必须作为一个系统评测

Coding Agent 的真实吞吐来自模型推理、交互协议与执行 Harness 的组合；只替换模型而不复测完整任务链会漏掉关键收益与风险。

  • OpenAI 报告 GPT-6 Astra 配合更新后的 Codex harness，在 Mind2Web 上相对当前 GPT-5.6 Sol 体验实现约 1.9 倍更快的任务完成速度。证据：GPT-6 Astra: A new generation of intelligence
  • GPT-6 Astra 在 Codex 中可以提出聚焦问题，同时继续推进不依赖答案的工作，并在关键决策需要用户输入时等待。证据：GPT-6 Astra: A new generation of intelligence
  • OpenAI 报告 Astra 在 OSWorld 2.0 得分 72.6%，单任务约 40 分钟；GPT-5.6 Sol 为 65.7%，单任务约 75 分钟。证据：GPT-6 Astra: A new generation of intelligence

限制：这些 benchmark 与耗时均来自 OpenAI 官方评测，真实仓库中的收益需要按任务类型重新验证。；更快完成任务不自动意味着更低总成本；并发数、重试、人工 review 与工具调用仍会影响端到端资源消耗。

Agent 平台开始用固定契约管理快速演进的客户端

当 Agent Server、浏览器客户端和自动化层独立演进时，API schema 必须被固定到可复现版本，并把 drift 变成 CI 可见失败。

  • OpenHands software-agent-sdk v1.45.0 于 2026-09-07 发布，并为 Agent Server 提供多平台二进制、openapi.json 与 SHA256SUMS 等发布产物。证据：OpenHands software-agent-sdk v1.45.0
  • v1.45.0 的 TypeScript client 明确面向浏览器并支持 remote conversations，但官方标记为 alpha，说明 API 仍可能发生破坏性变化。证据：OpenHands Agent Server TypeScript Client v1.45.0
  • OpenHands TypeScript client 从 package 配置中固定的精确 Agent Server release 获取 openapi.json，CI 会重新生成 schema 并在发生差异时失败。证据：OpenHands Agent Server TypeScript Client v1.45.0
  • OpenHands 将对 SDK main 的 drift 检查放到单独的周期审计，并记录精确 commit SHA；普通客户端 PR 不从持续移动的 main 生成契约。证据：OpenHands Agent Server TypeScript Client v1.45.0

限制：TypeScript client 当前仍是 alpha，不适合作为稳定生产 API 的成熟度证明。；OpenAPI 能约束接口形状，但不能独立保证事件顺序、执行语义或跨版本行为完全兼容。

长运行 Agent Runtime 需要知道“正在运行的是哪一代进程”

当 Agent Server 可以长期驻留、重启和替换时，build identity、process generation 和 stale-state recovery 应成为显式 Runtime contract。

  • OpenAI Codex rust-v0.154.0-alpha.6 于 2026-09-07 发布为 prerelease，该 tagged source 包含 exec-server build identity 与 app-server daemon PID lifecycle 相关变更。证据：Codex rust-v0.154.0-alpha.6
  • Codex exec-server 在接受连接前缓存当前 executor 的 build identity，并基于 build commit 与 target 生成 provider_id 写入 EnvironmentInfo。证据：Codex exec-server build identity
  • Codex app-server daemon 的 PID record 同时保存 pid 与 process_start_time，PID reservation 用锁串行化 detached launch，并用启动时间判断 stale record 是否仍对应同一进程。证据：Codex app-server daemon PID lifecycle
  • Codex 的 PID-managed stop 路径先请求受管 app-server 正常关闭，经过 grace period 后才强制终止，并持续校验记录对应的进程是否仍然存活。证据：Codex app-server daemon PID lifecycle

限制：该 Codex 版本是 alpha prerelease，Runtime 设计仍可能快速变化。；PID 与 build identity 解决的是进程代际和兼容性可见性，不能替代任务级幂等、状态恢复与权限控制。

From signals to action

  • 开始记录 Agent Workdays 与 Steering 时间

    同时统计 Agent 并发运行量、成功任务数、人工 review 与纠偏耗时，找出真正限制吞吐的控制环。

  • 把模型和 Harness 作为一个版本单元评测

    每次模型或 Harness 变化都跑同一组端到端任务，记录成功率、完成时间、重试和人工介入，而不是只比较模型 benchmark。

  • 为 Agent API 建立 Pinned Contract CI

    将客户端绑定到精确服务版本和 schema artifact，PR 中禁止从 moving main 生成契约，并把 drift 作为可见失败处理。

  • 给长运行 Runtime 增加代际身份

    在握手和状态记录中携带 build identity 与 process generation，并为 stale PID、重启和进程替换建立可测试恢复路径。
