Agent 进入分层运行栈，Harness 与协调器正在成为独立产品层

从 OpenAI 把 Codex Harness 作为托管 Agents API 提供，到 Cursor 用 Project Coordinator 管理长期上下文与大规模子 Agent，再到 SWE-2、DeepSeek V4.1 Flash 和 GPT-Live-1 分别优化行动效率、上下文成本与交互前端，Agent 工程的竞争焦点正在从单模型能力转向模型、Harness、协调器、执行环境和交互层的协同设计。

Four signals

  • Harness 正从应用内部实现变成可托管的平台能力

    OpenAI Agents API 将 Codex 的上下文管理、工具使用、多 Agent 与执行环境能力通过公共 API 暴露，开发者可以把 Harness 与业务工具和环境解耦。

  • 协调器开始管理长期项目而不是单次任务

    Cursor Projects 让 Coordinator 维护跨月上下文、分派云端与本地 Agent，并通过订阅持续响应 Slack、PR 或定时信号，工作单元正在从单次会话升级为长期项目。

  • Coding Agent 的优化目标正在从最高分转向成本与动作效率

    Cognition 的 SWE-2 把训练目标直接放到能力与成本的 Pareto 前沿，并报告相较 SWE-1.7 用更少步骤完成更多任务，说明 Agent 模型开始显式优化探索和行动预算。

  • 模型、Harness 与交互前端开始分层独立优化

    DeepSeek V4.1 Flash 针对长上下文 KV 成本设计并同步进入 DeepSeek Harness，而 GPT-Live-1 将低延迟全双工交互与后端推理及工具调用分离，Agent 栈正在形成清晰分层。

Agents API 把 Codex Harness 变成托管运行层

当上下文压缩、工具检索、多 Agent 调度和 Sandbox 生命周期由平台统一维护时，应用侧可以把更多精力放在业务工具、知识和审批边界，而不是重复实现 Agent Harness。

  • OpenAI 于 2026-09-10 将 Agents API 以 public beta 形式发布，声明该 API 使用与 Codex 相同的 Harness 与基础设施，并允许通过一次 session 创建调用指定任务、模型、工具和环境。证据：Introducing the Agents API
  • Agents API 允许开发者选择 OpenAI 托管 Sandbox、自有基础设施或合作伙伴 Sandbox，OpenAI 负责维护 Harness，而执行环境可以由应用自行决定。证据：Introducing the Agents API
  • OpenAI 文档将自动上下文压缩、Tool Search、Programmatic Tool Calling 与 Multi-Agent 支持作为 Agents API 的运行时能力，其中子 Agent 保持独立上下文并由主 Agent 汇总结果。证据：Introducing the Agents API · Agents API documentation

限制：Agents API 仍处于 public beta，接口、能力边界和定价方式可能继续变化。；托管 Harness 可以降低应用实现成本，但业务权限、数据边界和任务验收仍需要调用方自行设计。

Cursor Projects 把 Agent 编排提升到长期项目层

当 Coordinator 不再亲自写代码，而是维护长期上下文、分派执行 Agent 和持续接收外部事件时，Agentic coding 的核心控制面开始接近 Project Manager 与 Runtime Scheduler 的结合体。

  • Cursor Projects 宣布可以为 feature、migration 或完整应用维护跨月上下文，并由一个 Coordinator 将工作委派给大量子 Agent。证据：Introducing Projects
  • Cursor 明确说明 Project Coordinator 自身不写代码，而是规划任务、创建和管理执行 Agent，并把完成结果带回给用户检查。证据：Introducing Projects
  • Project 在独立云端机器运行，需要本机测试时可启动 local agent；同时支持监听 Slack、按计划运行或跟踪 PR，以外部信号触发后续委派。证据：Introducing Projects

限制：Cursor Projects 当前处于 beta，官方描述的数千 Agent 并发能力不代表每类项目都需要或适合如此规模。；长期共享上下文提高复用效率的同时，也要求更严格地管理过期知识、错误经验和权限继承。

SWE-2 把动作效率直接纳入 Coding Agent 优化目标

Coding Agent 的训练正在从单一成功率转向成本、步骤数和任务质量的联合优化；更强的工程判断如果能减少无效探索，就可能比单纯扩大推理预算更有实际价值。

  • Cognition 官方报告 SWE-2 在 FrontierCode 1.1 Main 上达到 50.0%，并称其相较 Fable 5.1 成本低 64%；这些结果属于厂商自报 benchmark。证据：Introducing SWE-2 Pushing the Pareto Frontier
  • Cognition 报告 SWE-2 medium 相较 SWE-1.7 在 FrontierCode 1.1 Main 上平均步骤减少 58%，平均成本降低 81%，首次真实编辑的中位步骤从 48 降至 18。证据：Introducing SWE-2 Pushing the Pareto Frontier
  • SWE-2 的后训练方法在一次 RL 运行中训练多个 reasoning effort level，并使用与各 effort 局部 Pareto 斜率匹配的成本惩罚来同时优化成功率与成本。证据：Introducing SWE-2 Pushing the Pareto Frontier

限制：benchmark、成本与行为数据主要来自 Cognition 自有评测体系，仍需要在真实仓库和不同任务分布上独立复核。；更少步骤不天然意味着更高可靠性，减少探索可能在陌生或高风险代码库中放大遗漏上下文的风险。

DeepSeek 正把长上下文模型与 Harness 作为一体化 Agent 栈发布

当模型架构直接针对 Agent 的长上下文成本设计，同时 Harness 默认适配该模型并补齐 Session、Steer 与进程生命周期能力时，开放模型生态也开始走向 Model × Harness 协同优化。

  • DeepSeek-V4.1-Flash 模型卡描述其为 552B backbone 的多模态 MoE，支持最长 1M token 上下文，并在 prefill 激活 8B 参数、decode 激活 16B 参数。证据：DeepSeek-V4.1-Flash Model Card
  • DeepSeek 官方称 V4.1 Flash 通过 CED、CSA2 与 FP4 KV caching 将 global KV cache 降至约 890 bytes per token，约为 DeepSeek-V4-Flash 的四分之一。证据：DeepSeek-V4.1-Flash Model Card
  • DeepSeek Harness v0.1.5-rc.1 新增 DeepSeek-V41-Flash 适配，并将其作为未显式配置模型时的新 Session 默认模型，同时支持 text、image 与历史中的 system prompt 更新。证据：DeepSeek Harness v0.1.5-rc.1
  • 同一 Harness release 增加可继续对话子 Agent 的排队与 Steer 操作，并将 Session persistence 改为 SessionHandle 生命周期模型，引入 session lock 以保证同一 Session 最多被一个进程持有。证据：DeepSeek Harness v0.1.5-rc.1

限制：DeepSeek-V4.1-Flash 的架构效率与 benchmark 结果主要来自官方模型卡，部署成本仍强依赖具体推理框架和硬件。；DeepSeek Harness v0.1.5-rc.1 是 prerelease，Session 格式和插件 API 已发生破坏性变化，不适合作为稳定协议直接锁定。

GPT-Live-1 把实时交互与深度推理拆成独立层

对需要持续对话的 Agent，低延迟感知和发声不必与复杂推理绑定在同一个模型中；交互前端可以保持实时性，再把需要搜索、规划或工具调用的工作委派给后端 Agent。

  • OpenAI 于 2026-09-10 发布 GPT-Live-1 API，模型可以同时监听和说话，并将 reasoning 与 tool calling 委派给 GPT-6 Astra 等后端文本模型或第三方模型。证据：Build more natural voice experiences with GPT-Live-1 in the API
  • GPT-Live-1 API 的前端 voice layer 官方定价为每分钟 0.05 美元，后端模型与 Agent Harness 可以独立选择和计费。证据：Build more natural voice experiences with GPT-Live-1 in the API
  • OpenAI 官方评测称 GPT-Live-1 相较 GPT-Realtime-2.1 在 Full Duplex Bench 提升 30 个百分点，并在与 GPT-6 Astra medium 配对时于 Tau3 排名第一；这些结果属于厂商自报。证据：Build more natural voice experiences with GPT-Live-1 in the API

限制：语音 Agent 的最终延迟和成功率还取决于网络、后端模型、工具调用与业务系统响应时间。；官方 benchmark 不能替代具体行业场景中的端到端对话质量、误操作和安全评测。

From signals to action

  • 把 Agent Runtime 能力从模型配置中拆出来

    为 context management、tool discovery、multi-agent、sandbox 与 session lifecycle 建立独立能力矩阵，避免把 Runtime 差异误认为模型差异。

  • 为长期任务增加 Project-level 控制面实验

    选择一个跨多日的真实开发任务，验证共享上下文、事件触发、Coordinator 与多个执行 Agent 的职责边界和恢复成本。

  • 用步骤数和成本补充 Coding Agent 成功率

    在现有代码任务评测中同时记录首次编辑时间、总工具调用、总步骤、token 与实际费用，观察更高成功率是否伴随可接受的执行成本。

  • 验证 Model 与 Harness 的组合而不是单测模型

    对同一任务固定仓库与验收标准，交叉测试不同模型和 Harness，比较长上下文、Steer、Session 恢复与 Tool contract 对结果的影响。
