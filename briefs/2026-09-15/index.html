科学模型开始原生携带 Agent Runtime，Intern-S2 把长程任务与专用模态合进开放栈

Intern-S2-397B 正式版把科学文献原页预训练、跨二十多个领域的强化学习、沙箱中的长程 Agent 训练、工具调用与时间序列等专用模态放进同一开放模型栈；更值得关注的是，部分能力已经明确依赖具体 Runtime 与协议桥接，说明开放模型竞争正在从单独权重扩展到 Model × Runtime × Agent Protocol 的联合工程。

Four signals

  • 科学数据开始绕过“先解析成纯文本”的入口

    Intern-S2-397B 的视觉预训练直接学习科学文献原始页面，把符号语义与视觉关系放进同一表示空间，科学模型的数据入口正从文本流水线扩展到页面级多模态。

  • 长程 Agent 能力正在成为模型训练目标

    Intern-S2-397B 将多个 Agent framework 接入大规模沙箱环境进行长程强化学习，Agent 能力不再只是推理时 Harness 的外挂行为。

  • 专用模态正在暴露 Runtime 绑定

    官方模型卡允许多种推理框架部署核心模型，但当前时间序列推理只支持 LMDeploy，说明“模型支持某模态”与“任意 Runtime 都能承载它”已经不是同一件事。

  • 模型别名与退役计划必须进入运行时治理

    InternLM 同时提供显式模型 ID、动态 latest 别名与 Preview 退役时间，并让响应暴露实际 ref_model；生产 Agent 需要把模型解析结果当成可观察部署状态。

科学预训练开始直接消费原始页面

当模型能直接从论文页面学习公式、图表与文本之间的关系时，科学 Agent 的上游数据工程可以少依赖易丢失版面语义的中间解析层，但数据质量与视觉歧义仍需要单独验证。

  • Intern-S2-397B 的官方说明称其视觉预训练直接从科学文献原始页面学习，不经过中间解析，并在共享表示空间中联合建模符号语义与视觉关系。证据：Intern-S2-397B Model Card · Intern-S Series Official Repository
  • Intern-S2-397B 将多样化科学强化学习任务扩展到二十多个领域并进行联合训练，官方列举的专用任务包括生物分子相互作用设计与材料结构生成。证据：Intern-S2-397B Model Card · Intern-S Series Official Repository

限制：原始页面预训练减少中间解析并不意味着消除 OCR、版面歧义或科学符号误读风险。；专业任务能力与效果主要来自官方说明，仍需要在具体科研工作流上独立复核。

长程 Agent 行为已经进入模型训练闭环

Agent 能力正在从“模型 + 外部脚手架”的推理时组合，前移到由交互环境和沙箱任务共同塑造的训练目标；因此评估模型时也需要同时观察其所处的 Harness 与环境约束。

  • Intern-S2-397B 通过把多个 Agent framework 连接到大规模沙箱环境，执行面向通用与科学长程任务的 black-box agentic reinforcement learning。证据：Intern-S2-397B Model Card · Intern-S Series Official Repository
  • Intern-S2-397B 模型卡说明 thinking mode 默认开启，并明确不建议在 agentic tasks 中关闭 thinking mode。证据：Intern-S2-397B Model Card
  • Intern-S2-397B 的官方使用说明提供 OpenAI 风格的 tools/tool_choice 调用示例，模型输出可以进入标准化工具调用循环。证据：Intern-S2-397B Model Card

限制：沙箱强化学习能够塑造长程行为，但并不能证明模型在未见过的真实工具和权限边界下同样可靠。；thinking mode 的官方建议属于模型提供方经验，仍需结合任务成本、延迟和失败模式做本地回归。

模型能力与 Runtime 能力开始出现非对称

开放权重并不自动意味着部署能力可互换；当时间序列等模态只在特定 Runtime 可用时，Runtime 兼容矩阵本身就必须成为模型选型和发布门禁的一部分。

  • Intern-S2-397B 官方模型卡给出 LMDeploy、vLLM 与 SGLang 三种部署路径，说明核心模型并不绑定单一推理框架。证据：Intern-S2-397B Model Card
  • 同一模型卡同时注明时间序列推理目前仅由 LMDeploy 支持，并提供地震波形与时间序列预测的专用输入示例。证据：Intern-S2-397B Model Card
  • 官方评测说明对文本推理使用最高 256K token 推理长度，对多模态 benchmark 使用最高 64K token 推理长度。证据：Intern-S2-397B Model Card · Intern-S Series Official Repository

限制：官方支持列表会随 Runtime 更新而变化，部署前应以具体版本的兼容性测试为准。；benchmark 的最大推理长度不等同于每个生产场景都能以相同吞吐、显存和延迟稳定运行。

OpenAI 与 Anthropic 兼容协议正在成为 Harness 接口层

当同一模型既能通过 OpenAI-compatible endpoint 接入普通 Agent framework，也能通过 Anthropic-compatible gateway 驱动 Claude Code 时，协议兼容层正在把模型、Harness 与客户端生命周期进一步解耦。

  • Intern-S2-397B 官方 Agent 集成说明支持通过自托管 LMDeploy 暴露 OpenAI-compatible endpoint，再由 Agent framework 以标准 client 接入。证据：Intern-S2-397B Model Card
  • 官方说明同时给出 LMDeploy 的 Anthropic-compatible /v1/messages 路径，用于把自托管 Intern-S2 接入 Claude Code。证据：Intern-S2-397B Model Card
  • InternLM 官方 API 路径同时提供 OpenAI-compatible 调用方式，以及面向 Claude Code 的 Anthropic-compatible gateway。证据：Intern-S2-397B Model Card

限制：API 形状兼容不代表工具语义、错误类型、流式事件和上下文管理完全等价。；在跨协议接入前仍应对 tool call、取消、重试、长上下文和多模态消息做端到端契约测试。

动态模型别名需要像依赖版本一样治理

当 latest 别名可以重新指向新模型、Preview 模型存在明确退役日期时，Agent Runtime 应记录解析后的实际模型并允许显式 pin，而不是把字符串别名当成稳定能力合同。

  • InternLM 官方模型文档将正式版 Intern-S2 暴露为模型 ID intern-s2，标注 397B 参数规模、256K context，并说明 thinking mode 默认开启。证据：InternLM API Models
  • 官方文档建议使用 intern-latest 获取当前最新模型，并通过响应中的 ref_model 字段确认实际路由到的模型；示例响应显示 ref_model 为 intern-s2。证据：InternLM API Models
  • InternLM 官方文档标记 Intern-S2-Preview-397B 将在 2026-10-31 退役，并建议新集成使用显式版本 ID。证据：InternLM API Models

限制：latest 别名适合快速跟进新模型，但会把行为漂移引入长期 Agent，因此生产任务更适合显式版本与受控升级。；模型退役日期和别名指向属于服务运营状态，发布前需要重新查询而不是长期缓存。

From signals to action

  • 为模型路由记录实际 ref_model

    对所有使用 latest 或 provider alias 的 Agent 请求持久化显式请求模型与实际解析模型，升级时以差异触发回归验证。

  • 建立 Model × Runtime 能力矩阵

    固定同一 checkpoint，分别验证 LMDeploy、vLLM 与 SGLang 的文本、图像、tool call、长上下文和专用模态支持，不把“模型支持”误写成“所有 Runtime 支持”。

  • 把 thinking mode 纳入 Agent 回归配置

    将 thinking 开关、预算、延迟和成功率一起版本化，对长程任务先保持官方推荐默认值，再用受控实验决定是否调整。

  • 用沙箱长任务验证科学 Agent

    设计需要多步工具调用、状态恢复和结果校验的科学任务，在隔离环境中记录失败位置、证据链和人工接管点。
