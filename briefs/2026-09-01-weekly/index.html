Orbis Weekly — Presentation Becomes a Platform Boundary

A weekly judgment on how Orbis moved from a Daily-only slide path toward a reusable structured publishing and discovery platform.

Weekly Thesis

The most important change this period is that presentation generation stopped being a Daily-specific output path and became a reusable boundary between structured content, rendering, discovery and verification.

Trend Movements

rising · agent-harness

Presentation generation now converges through source-neutral descriptors and an explicit template registry instead of a Daily-only rendering path.

new-variable · coding-agent

Standalone structured Presentations now publish beside Brief-derived decks without committing generated Slidev sources or adding a second build pipeline.

Key Sections

Descriptor and registry replace Daily-specific dispatch

Presentation generation now has a source-neutral contract before rendering, which makes new sources and templates additive rather than invasive.

  • PR 11 introduced PresentationDescriptor and Template Registry while keeping daily-v1 output and build-slides behavior stable.
  • The generator adapts Brief content before template dispatch instead of embedding Daily rendering decisions in the build stage.

限制：The registry currently covers daily-v1 and talk-v1; Weekly rendering remains the next planned template capability.

A second structured source validates the platform boundary

Standalone Presentation content now reaches the same generated Slidev and public Slides surfaces without becoming a duplicate reading-content system.

  • PR 12 added content/presentations and talk-v1 while keeping build-slides template-agnostic.
  • Slides discovery now lists both Brief-derived and standalone Presentation sources with independent public base paths.

限制：Standalone Presentation remains intentionally outside generic Archive, Topic and RSS semantics.

Verification becomes part of the product contract

Each platform expansion is now guarded by source validation, negative cases, mixed builds and trusted Preview evidence rather than only by successful rendering.

  • Plan 20 validation covers invalid sources, unsupported templates, duplicate slugs, non-public visibility and independent deck base paths.
  • Trusted Preview publishing rebuilds from the read-only PR artifact and performs public availability smoke checks before surfacing the URL.

限制：Weekly-specific rendering and mixed Daily plus Weekly plus Talk presentation verification are intentionally deferred to Plan 30B.

Next Period Watch

  • Weekly semantics through the shared content system

    A real Weekly should prove cadence-specific judgment can reuse Brief discovery, RSS, Topic and Archive infrastructure without inheriting Daily body semantics.

  • weekly-v1 through the existing registry

    Plan 30B should add Weekly presentation rendering without changing build-slides or weakening the Daily 11-slide contract.
